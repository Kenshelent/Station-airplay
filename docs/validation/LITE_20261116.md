# Лайт: громкость AirPlay 16 ноября 2026

Проверка на живой Яндекс Станции Лайт, runtime model ID `yandexmicro`.
Итог: звук AirPlay на этой прошивке не масштабируется ни логическим уровнем
Quasar, ни ALSA-контролом `Master`, поэтому громкость ползунка должен применять
сам приёмник. Пакет переключает Лайт на этот путь и миграцией снимает
`native_volume` у уже установленных конфигураций.

## Окружение

| Параметр | Значение |
|---|---|
| Модель из `/api/device` | `yandexmicro` |
| Прошивка (`version_full`) | `0.369.1.46.4778262442.20261013.297` |
| Device tree compatible | `yandex,station-micro`, `amlogic, axg` |
| Ядро | Linux, AArch64, Amlogic AXG |
| Userspace ABI | ARMhf: ELF class `01`, machine `28 00` |
| Luna | 0.2.28 при проверке; релиз 2.1.12 требует 0.2.29 |
| Пакет | `airplay/airplay-luna` 2.1.11, затем локальная сборка 2.1.12 |
| `/etc/asound.conf` | `default` → `soft_volume` → `dmix_spk_plug` → `dmix` → `hw:0,0` |
| mDNS | `_airplay._tcp` от штатного имени `yandexmicro-…`, модель `AudioAccessory5,1` |

Серийный номер, MAC-адреса, токены и имя комнаты в отчёт не включены.

Проверка выполнена на Luna 0.2.28. Релиз 2.1.12 требует 0.2.29: в ней
перезапуск демона после установки сохраняет аргументы, а нативная громкость
Лайта выбирается по device-tree. Обновление кнопкой из панели проверено
отдельно на стенде `yandexplum` с Luna 0.2.29 (2.1.11 → 2.1.12).

## Причина

Профиль плагина и приёмник подходят: PCM `plug:dmix_spk`, ARMhf-приёмник,
общий микшер Quasar. Ошибка была в том, кто применяет громкость отправителя.

Luna выбирает нативный backend `quasar_volume` по паре «точный номер сборки +
элемент device tree». Для этой сборки в `src/quasar_volume.rs` был указан
`yandex,yandexmicro`, то есть model ID, а реальная плата объявляет
`yandex,station-micro` (тот же токен Luna уже использует в `install.sh`).
Квалификация не проходила, и Luna писала ALSA `Master` напрямую. Чтение
`GET /api/volume` возвращало это же зеркало.

Сам протокол на станции работает. Ручная отправка `VolumeSet` через
`iohub_clients` на этой сборке прошла с подтверждением:

| Действие | Логическое состояние Quasar | ALSA `Master` |
|---|---|---|
| Исходно | 20% | 33% |
| `VolumeSet 60` | ACK 60% | 60% |

То есть `maind` принимает внешний уровень и зеркалит его в ALSA. Нативный путь
Luna после исправления токена будет работать, но слышимую громкость AirPlay он
на этой прошивке всё равно не меняет — см. следующий раздел.

## Почему нативный и ALSA-уровень не слышны в AirPlay

Проверки на той же колонке, при играющей AirPlay-музыке:

- кнопки громкости на корпусе не меняют громкость AirPlay;
- «Алиса, громче» и «Алиса, громкость пять» не меняют громкость AirPlay;
- `SPK mute` (`numid=177`) не устанавливается: запись `on`/`1` не сохраняется;
- `Master` (`numid=178`, 0–255, −51…0 dB) меняет значение, но не звук:
  прямой `aplay -D plug:dmix_spk` одного и того же файла при `Master` 100% и
  5% звучал одинаково.

При этом штатная музыка Алисы на слух меняется и двигает `Master`
(наблюдение 30% → 75% → 50% по кнопкам), а программный `softvol`-контрол в
списке микшера не появляется. Значит `maind` ослабляет свой тракт внутри
себя, а AirPlay идёт отдельным процессом в `dmix` и остаётся неослабленным.
`/etc/asound.conf` подтверждает, что `dmix` идёт в `hw:0,0` мимо тракта
`maind`.

Вывод: на этой прошивке громкость AirPlay обязана масштабироваться в
приёмнике. Проверено без пересборки: удаление `ignore_volume_control` из
`/run/station-airplay/shairport.conf` и перезапуск приёмника включили
штатную софтверную громкость shairport; владелец подтвердил, что ползунок
телефона теперь меняет слышимую громкость.

## Что изменено в 2.1.12

- Цель `yandexmicro` в `release/yampkg/targets.json` выпускается с
  `native_volume: false`. При этом флаге `receiverControlConfig` не добавляет
  `ignore_volume_control`, и shairport применяет громкость AirPlay сам в
  пределах `volume_range_db = 50`.
- `controlsDefaultsVersion` поднят до 4, добавлено правило
  `yandexmicro: native_volume true → false`. Оно срабатывает только если
  владелец не менял поле; остальные флаги не затрагиваются.
- Голос, ducking, индикация и native player остаются включены как раньше.

Ограничения этого пути:

- кнопки станции и Алиса во время AirPlay-сессии не меняют громкость потока:
  их уровень к `dmix` этой прошивки не применяется;

- проверена **одна** сборка: `0.369.1.46.4778262442.20261013.297`. На другой
  сборке, где уровень станции доходит до AirPlay‑пути, дефолт
  `native_volume: false` может быть не нужен. После миграции до версии 4
  значение `native_volume` больше не перезаписывается автоматически (правило
  срабатывает только если владелец не менял поле), поэтому на такой сборке
  можно вручную вернуть `native_volume: true` в `airplay-controls.json` — и
  оно сохранится;

## Исправление в Luna

В `src/quasar_volume.rs` для этой сборки теперь требуется точный элемент
device tree `yandex,station-micro` вместо `yandex,yandexmicro`. Похожие имена
(`prefix-yandex,station-micro`, `yandex,station-micro-suffix`) и model ID
квалификацию не проходят. Добавлены тест точной пары и проверка сохранения
прежних квалификаций.

Это исправляет логическое состояние и `GET /api/volume`, но не делает
громкость AirPlay слышимой на этой прошивке: для неё нужен путь из предыдущего
раздела. Обе правки независимы и оформляются отдельными PR.

  удаления `ignore_volume_control`.

## Откат

- Вернуть `native_volume: true` в `airplay-controls.json` и перезапустить
  службу плагина: вернётся прежнее поведение с `ignore_volume_control`.
- На время проверки исходные файлы сохранены на станции в `/tmp`; после
  перезагрузки они не нужны, конфигурация приёмника создаётся заново.
